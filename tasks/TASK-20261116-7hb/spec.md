<Spec — AI Catalog Lean Cards & Skill Detail Pages>
## Feature Summary
Redesign the AI Catalog skill cards to be lean, concise, and interactive, while introducing dedicated standalone static detail pages for each skill (`docs/skills/<name>.html`). Skill cards on `index.html` will display only the title, badges, right chevron affordance, and a 1-sentence summary, replacing the previous expandable full descriptions and raw source links. The entire card will become clickable via an accessible stretched-link pattern with a subtle 2px lift, royal-blue border, and sliding chevron hover animation. Dedicated detail pages will be statically generated by `tools/build_site.py` using a zero-dependency pure-Python Markdown parser, rendering frontmatter metadata and formatted Markdown bodies within a clean 48rem single-column view with smart breadcrumb navigation.

## Acceptance Criteria
1. **Lean Card Content**: Each skill card in the catalog grid (`index.html`) displays only the skill title, category/metadata badges, a right chevron affordance (`→`), and a concise 1-sentence summary derived from the skill description.
2. **Removed Card Clutter**: The "Show full description" toggle button and footer source/file links are removed from all skill cards on `index.html`.
3. **Accessible Stretched Link**: Each skill card is fully clickable via an accessible stretched-link anchor (`<a class="card-link" href="skills/<name>.html">` with `::after` covering the card container), preserving keyboard focus navigation (Tab, Enter) and native browser behaviors (Cmd/Ctrl-click, middle click, right-click menu).
4. **Card Hover Animation**: On hover or focus, the skill card elevates with `transform: translateY(-2px)`, transitions border color to royal-blue (`#004AAD`), and displays `cursor: pointer`.
5. **Chevron Slide Animation**: On card hover or focus, the right chevron arrow (`→`) in the title row slides horizontally with `transform: translateX(3px)`.
6. **Smooth Transition & Shadowless Design**: Card hover transitions use `transition: 180ms ease` on transform and border-color. In accordance with DESIGN.md, no box shadows (`box-shadow`) are added.
7. **Reduced Motion Compliance**: Under `@media (prefers-reduced-motion: reduce)`, card lift (`translateY`) and chevron slide (`translateX`) transforms and transitions are disabled (`transform: none`, `transition: none`), retaining border color change only.
8. **Full Description Search Indexing**: The client-side real-time search on `index.html` continues indexing the full skill name and complete description text (`s.name + " " + s.description`), allowing users to find skills by deep keywords not visible in the 1-sentence summary.
9. **Search Filter State Retention**: When search filters or category tags are applied or cleared on `index.html`, matched cards retain identical clickable stretched-link behavior, hover animations, and styling.
10. **Static Detail Page Generation**: Executing `python3 tools/build_site.py` generates 45 standalone static HTML pages located at `docs/skills/<name>.html`, corresponding to each skill file in the skills directory.
11. **Directory Auto-Creation**: `tools/build_site.py` automatically creates the output directory `docs/skills/` if it does not already exist.
12. **Pure Python Standard Library**: The Markdown parser in `tools/build_site.py` relies strictly on the Python standard library with zero external pip dependencies and executes cleanly under `python3 -I`.
13. **Detail Page Metadata Card**: Each skill detail page features a top metadata summary card displaying skill title, category badge, and available frontmatter attributes (e.g. description, arguments, tags).
14. **Markdown Body Rendering**: The full Markdown body of each `SKILL.md` (below the YAML frontmatter) is rendered into semantic HTML beneath the metadata card, correctly converting headings (`h1`–`h4`), ordered and unordered lists, blockquotes, inline formatting (`**bold**`, `*italic*`, `` `code` ``), links, and fenced code blocks (`<pre><code>`).
15. **HTML Entity Escaping**: Markdown code blocks and raw text are properly HTML-escaped (`&`, `<`, `>`, `"`) to prevent unescaped markup injection or display breakage.
16. **Detail Page Reading Layout**: The skill detail page is rendered in a single-column layout capped at a reading width of `48rem` (`max-width: 48rem; margin: 0 auto;`).
17. **Smart Breadcrumb Navigation**: The detail page top navigation includes a back link (`← Back to catalog` / `Catalog > [Category]`).
18. **Referrer-Aware Back Navigation**: Clicking the `← Back to catalog` link calls `history.back()` if `document.referrer` contains the catalog (`index.html`), falling back to `href="../index.html#skills"` when visited directly or in a new tab.
19. **Shared Stylesheet Architecture**: `skill_template.html` reuses the styling block (`/*STYLE*/`) extracted from `template.html` during `build_site.py`, ensuring consistent typography, CSS variables, code block styles, and color palette with zero design drift.
20. **Specialist Agents Isolation**: Specialist agent cards on `index.html` remain inline as currently implemented and are not converted into stretched-link detail pages in this phase.

## Out of Scope
- Dedicated detail pages for Specialist Agents (agents remain inline on `index.html`).
- External pip dependencies or third-party Markdown rendering packages (e.g. `markdown`, `mistune`, `pandoc`).
- Dynamic server-side rendering (SSR), databases, or client-side SPA routing (all pages are strictly static HTML).
- Global search indexing of the full detail page Markdown body text on `index.html` (search index covers skill name and description).
- Drop shadows (`box-shadow`) on hover or detail cards, strictly prohibited by DESIGN.md.

## Fallback Behaviors
- **Navigation Referrer Fallback**: If `document.referrer` is empty, external, or does not include `index.html`, clicking `← Back to catalog` navigates directly to `../index.html#skills` via standard anchor `href`.
- **Missing Frontmatter Attributes**: If a `SKILL.md` frontmatter lacks optional attributes, the metadata card renders available fields gracefully without build errors or displaying `None`/`undefined`.
- **Reduced Motion Support**: If the user has `prefers-reduced-motion: reduce` configured in their browser/OS, hover animations degrade gracefully to color and border shifts with no motion transforms.
- **Missing Output Directory**: If `docs/skills/` does not exist prior to running `build_site.py`, the script automatically creates it with `os.makedirs(..., exist_ok=True)`.

## Resolved Ambiguities
- **Page Delivery Model** → Standalone static HTML files (`docs/skills/<name>.html`) generated at build time by `tools/build_site.py` for shareability, direct URL access, and offline compatibility (Settled Decision 1).
- **Markdown Parsing Engine** → Pure-Python standard library parser in `tools/build_site.py` with zero pip dependencies, compatible with `python3 -I` (Settled Decision 7).
- **Card Clickability Pattern** → Accessible stretched-link pattern (`<a class="card-link">` with `::after` overlay) to preserve middle-click, keyboard Tab navigation, and clean semantic markup (Settled Decision 5).
- **Hover Visual Style** → 2px translateY lift + royal-blue border (`#004AAD`) + chevron slide (`translateX(3px)`), strictly avoiding drop shadows per DESIGN.md (Settled Decisions 4, 10).
- **Card Content Density** → Lean cards displaying title, badges, chevron, and 1-sentence summary; removal of expandable description toggles and footer source links (Settled Decision 3).
- **Search Query Indexing** → Client-side search retains full name and complete description indexing (`s.name + " " + s.description`) while cards render lean text (Settled Decision 12).
- **Stylesheet Architecture** → `skill_template.html` reuses `/*STYLE*/` from `template.html` during `build_site.py` to ensure visual consistency and zero CSS duplication (Settled Decision 11).
- **Breadcrumbs & Back Navigation** → Smart breadcrumb back button using `history.back()` when referrer matches catalog, falling back to `../index.html#skills` (Settled Decision 9).
- **Agent Scope** → Skills only (45 skill detail pages); specialist agents remain inline on `index.html` (Settled Decision 6).
